# 架构

## 1. 项目是什么

SiriusRealLife 是一个**人格模拟器**。人格是一个**有限状态机 + 意识流**：

- 任一时刻只持有**一个**状态
- 状态由**随机分派器**（带权重、冷却、前置条件）选出，也可被事件抢占
- 状态 = 一段有明确出口的过程：目标 + 可用工具白名单 + 退出条件
- 时间由固定 **tick** 驱动，随机只在"该换状态了"这一刻介入

技术栈：**Go** 后端 + **Vue 3** 前端。LLM 全部经 AMKR（见 [`llm-amkr.md`](llm-amkr.md)）。

目标不是"一个会聊天的 LLM"，而是**一个能自己待着、自己决定下一秒干什么的存在**。行为要像个有作息的人，而不是一个等输入的问答接口。

## 2. 核心模型

五个概念，互相正交。**不要把它们合并**（合并会直接导致状态爆炸，见硬规则 R2）。

### 2.1 状态（state）

离散枚举，有明确出口条件。一个状态至少声明：

| 字段 | 说明 |
|---|---|
| `weight` | 基础权重，分派时参与加权抽取 |
| `guard` | 前置条件，不满足则不进入候选 |
| `minTick` / `maxTick` | 持续时长区间 |
| `cooldown` | 冷却期，刚离开的状态短期内不被选中 |
| `tools` | 该状态可用的工具白名单（字符串名，如 `["read_app"]`） |
| `onEnter` / `onExit` | 进入/退出时的副作用（只允许改心境与写意识流） |

状态**不携带情绪**。`ANGRY_WORKING` 是错的（R2）。

### 2.2 心境（mood）

连续量，随时间自己衰减，例如精力 / 烦躁 / 好奇 / 亲密度。心境不参与状态枚举，只做两件事：

- 影响分派权重（累了一天就更倾向"发呆"）
- 影响 prompt 文字与工具参数

影响方向是**单向**的：心境 → 权重/prompt/参数；状态 → 只能改心境和意识流。

### 2.3 分派器（dispatcher）

在"该换状态了"这一刻被调用。流程：

1. 过滤出满足 `guard` 且不在 `cooldown` 内的状态
2. 用当前心境调整权重
3. **排除当前状态**（除非该状态是被事件强制进入的）
4. 按权重抽取

抽取必须可复现：agent 持有自己的 `*rand.Rand`，种子显式传入（R3）。

### 2.4 tick

真实时间与游戏时间的换算**只在 tick 源头做一次**（R8）。业务逻辑只认 tick 序号，不认 `time.Now()`。

这样离线推演、加速、回放全部免费拿到 —— 也是唯一能让"跑 30 个 tick 验收"变成确定性测试的办法。

### 2.5 意识流（memory）

三层，必须分开且必须有界（R5）：

| 层 | 用途 | 边界 |
|---|---|---|
| `stream` | 全量日志，可归档 | 不设硬上限，但不进 prompt |
| `working` | 最近 N 条 | 进 prompt 的就是这一层 |
| `longterm` | 压缩摘要 | 定期从 stream 压缩而来 |

**prompt 只读 `working` + `longterm`。** 任何往 prompt 里塞全量历史的代码都是 bug。

### 2.6 数据流

```
真实时间 ──► tick 源（唯一做时间换算的地方）
                │
                ▼
        ┌───────────────────────┐
        │  agent goroutine      │  ◄── 事件 channel（唯一入口）
        │  select { tick / 事件 }│
        └───────────┬───────────┘
                    │ 需要换状态 / 需要 LLM
                    ▼
              分派器（加权抽取）
                    │
                    ▼
        状态执行 ──► 工具调用 / LLM 调用（异步，可取消）
                    │
                    ▼
        写 working memory ──► 结构化转移日志（R6）──► SSE ──► Vue
```

**并发模型**：一个 agent 一个 goroutine，状态只被它自己改（R1）。其他 goroutine 想影响 agent 只能投递事件，不准持锁直接改状态。

## 3. 目录结构

```
cmd/agent/           程序入口，只做装配（读配置、建 agent、起 http），不放业务逻辑
internal/fsm/        状态机核心：状态定义、分派器、tick 循环、状态转移
internal/mood/       心境（连续量），影响分派权重与工具参数
internal/tools/      工具实现，每个工具一个文件
internal/llm/        LLM 客户端。唯一实现是 AMKR 的 OpenAI 兼容接口
internal/memory/     意识流三层：stream / working / longterm
internal/transport/  HTTP 路由 + SSE 推送 + AMKR WebUI 反代
config/              状态表、权重、prompt 模板
web/                 Vue 3 + Vite + TS 前端
docs/                本目录
```

新目录必须有明确归属，不进 `internal/` 就别建。禁止 `utils/`、`common/`、`helpers/`、`models/` 这类无主题垃圾桶。
